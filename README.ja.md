# Lifta

挙上記録を登録すると、その種目ごとに、あなたの体重と性別における世界トップ
レベルの基準と照らし合わせたランクが表示されます。ランクはブロンズ →
シルバー → ゴールド → プラチナ → ダイヤモンド → グランドマスターの6段階
です。競技は3つあり、それぞれ専用のタブとランクを持ちます。

* **パワーリフティング**（スクワット・ベンチプレス・デッドリフトの
  ビッグ3）— DOTS で採点。
* **ウエイトリフティング**（スナッチ・クリーン&ジャーク）—
  [シンクレア係数](https://en.wikipedia.org/wiki/Sinclair_coefficient)
  で採点。
* **自重トレーニング**（懸垂・ディップス・腕立て伏せ）— ストリクトな
  レップ数で採点し、加重分はレップ数に換算して加算。

これに加えて、3競技すべての達成度を平均した**総合力ランク**があります。
こちらは休眠・覚醒・進化・頂点・超越・**究極生命体**という独自の6段階です。
まだ取り組んでいない競技は0%として計算されるため、1競技だけを極めても
全体の3分の1程度で頭打ちになります。つまり総合力ランクは幅広さを評価する
指標であり、その最上位は3競技すべてで世界トップレベルにあることを意味し
ます。4つのランクのうちどれをバッジとして名前の横に表示するかは、
リフター自身が選べます。

種目ごとにランクが付き、その競技の全種目を登録すると競技全体のランクも
決まります。ダッシュボードには次のティアに必要な数値が表示されます
（「次: ゴールドまで 187.5 kg、または 162.5 kg × 5回」）。公開を選んだ
リフターは公開プロフィールを持ち、リーダーボードに掲載されます。
ダイヤモンド以上の記録は、管理者が承認するまでランクに反映されません。

アプリ全体が**英語と日本語**に対応しており、ヘッダーの言語ボタンで
切り替えられます。

## 動作要件

* Ruby（バージョンは `.ruby-version` を参照）
* SQLite3（`sqlite3` gem に同梱。別途サーバーを立てる必要はありません）

## セットアップ

```
bin/setup
```

gem のインストールと、開発用・テスト用データベースの準備をまとめて行い
ます。手動で行う場合は次のとおりです。

```
bundle install
bin/rails db:prepare
RAILS_ENV=test bin/rails db:prepare
```

## 起動

```
bin/rails server
```

起動後、http://localhost:3000 を開きます。`bin/rails db:seed`（開発環境
のみ）でデモ用アカウントが作成されます。パスワードはいずれも
`password123` です。

* `demo@example.com`: 3競技すべてに記録があるリフター
* `admin@example.com`: 管理者。承認待ちキューに記録が1件入った状態
* リーダーボードを埋めるための、公開設定のリフター数名

## 管理者

既存のアカウントに管理者権限を付与する（または剥奪する）には次のように
します。

```
bin/rails "admin:grant[you@example.com]"
bin/rails "admin:revoke[you@example.com]"
```

本番環境では、アプリのコンテナ内で実行します。

```
bin/kamal app exec --reuse 'bin/rails "admin:grant[you@example.com]"'
```

管理者のナビゲーションには**管理**リンクが表示され、承認待ちの記録件数が
併記されます。

* **承認待ちキュー**: ダイヤモンド以上にランクされた記録の一覧。承認
  （ランクとリーダーボードに反映されます）、却下（リフターの履歴には
  「却下」として残ります）、削除のいずれかを選べます。
* **ユーザー**: アカウントの検索、任意のユーザーの記録の閲覧、記録の削除、
  ユーザーの削除（記録・体重ログ・セッションも併せて削除）ができます。

管理者以外には、管理ページはすべて 404 を返します。

## 採点の仕組み

採点ロジックは `app/models/discipline` と、`Tier`・`Scale` にまとまって
います。

* **記録のスコアは計算式で求め、そのまま保存します**（`lifts.score`）。
  DOTS ポイント、シンクレアポイント、または体重換算レップ数です。2回
  以上のセットは、エプリー式で推定した 1RM を用いて換算します。この推定
  はレップ数が多いほど精度が落ちるため、パワーリフティングは10回まで、
  ウエイトリフティングは3回までを上限としています。
* **性別ごとの Scale が、スコアを世界トップレベル基準に対する割合に変換
  し**、その割合を `Tier` に対応させます（ブロンズ 0%、シルバー 40%、
  ゴールド 60%、プラチナ 75%、ダイヤモンド 90%、グランドマスター 100%
  から）。
  * パワーリフティングとウエイトリフティングは、種目と性別ごとに1つの
    「上限値」を用います（`CEILINGS`）。パワーリフティングの上限値の
    合計は DOTS 600ポイントになるよう設定してあるため、全種目で X%
    の位置にいれば、全体でもちょうど X% の位置になります。
  * 自重トレーニングには確立された計算式がないため、ティアごとのレップ
    数を明示的に定義しています（`THRESHOLDS`）。

  これらの数値はあくまで概算のキャリブレーションなので、自由に調整して
  構いません。ティアは保存していないため、上限値を変更してもマイグレー
  ションは不要です。
* **競技全体のランク**: パワーリフティングとウエイトリフティングでは、
  各種目のベスト記録の合計を上限値の合計と比較します（大会のトータルと
  同じ考え方です）。自重トレーニングでは、種目ごとの割合の平均を取り
  ます。
* **総合力ランク**（`ComboCard`・`ComboTier`）: 3競技の
  `Discipline#progress_percent` の平均です。この計算では、記録のない種目は
  「未ランク」ではなく0点として扱います。平均を取ると高い数値に届きにくく
  なるため、段階のしきい値は `Tier` より低め（15/30/50/70/90）に設定して
  いますが、それでも最上位に到達するには3競技すべてでダイヤモンド級の
  強さが必要です。2つのランク体系に共通する処理は `RankLadder` にまとめて
  あります。
* **妥当性チェック**: ダイヤモンド以上の記録は承認待ちとなります。
  世界トップレベル基準の200%を超える記録（入力ミスや kg/lb の取り違え）
  は自動的に却下されます。
* **計算式そのものを変更した場合**（上限値の調整ではなく）は、
  `bin/rails lifts:rescore` で保存済みスコアを再計算してください。

シンクレア係数は 2021〜2024 年のオリンピックサイクルの値です。新しい
階級の確定待ちのため、IWF は 2025〜2028 年の値をまだ公表していません。
DOTS は体重を公表されている適用範囲に丸めます（男性 40〜210 kg、
女性 40〜150 kg）。

## 多言語対応（English / 日本語）

ユーザーに表示される文字列はすべて `config/locales/en.yml` と
`config/locales/ja.yml` にあります。ビュー、フラッシュメッセージ、
バリデーションエラー、ランクアップ時のメッセージ、日付表記が対象です。
Rails 自体のメッセージは `rails-i18n` gem から取得しています。

* **訪問者に表示する言語**（`Localization` concern）は次の順で決定します。
  1. `?locale=` パラメータ（ヘッダーの言語ボタン、または共有リンク）
  2. 以前に選んだ言語（Cookie に保存）
  3. ブラウザの `Accept-Language`
  4. 英語
* **言語ボタン**は、切り替え先の言語をその言語自身で表示し（「日本語」／
  「English」）、現在のページと絞り込み条件を保ったまま切り替えます。
* **検索エンジンとリンクプレビュー**: 各ページは `hreflang` でもう一方の
  言語版を指しています。プロフィールの共有リンクは共有した人の言語を
  引き継ぐため、LINE・X・Slack でのリンクプレビューもその言語で表示され
  ます。
* **日本語のタイポグラフィ**: 仮名・漢字用のフォントスタックを指定し、
  行の高さをやや広げ、`word-break: auto-phrase` によって単語の途中では
  なく文節で改行されるようにしています。

**テキストを追加・変更するときは**、必ず両方のファイルにキーを追加して
ください。翻訳が欠けていると、開発環境とテスト環境では例外が発生します。
`spec/i18n_spec.rb` は、2つのファイルのキーや `%{placeholder}` がずれて
いると失敗します。`spec/requests/localization_spec.rb` は全ページを
日本語で描画して確認します。ビューでは遅延ルックアップを使ってください
（`lifts/index` 内の `t(".title")` は `lifts.index.title` を参照します）。

## 設計メモ

* **認証**には Rails 8 標準のクッキーセッション用ジェネレータを使って
  います（`User`、`Session`、`Current`、`Authentication` concern）。
  Devise は使用していません。
* **体重はプロフィールの項目ではなくログです**（`BodyweightEntry`）。
  体重は時間とともに変化するためです。各記録は**その記録の日付時点の**
  体重を保存するので（大会の計量と同じ考え方）、後から過去の日付で登録
  した記録も、当時の体重で採点されます。記録フォームから直接体重を入力
  することもでき、その値はログにも追加されます。
* **単位**: 表示単位（kg または lb）はユーザーが選べますが、データは
  すべてキログラムで統一して保存します。変換はコントローラの境界で
  `WeightConversion` により一度だけ行います。
* **タイムゾーン**: ユーザーごとに設定され、サインアップ時にブラウザから
  検出し、設定画面で変更できます。リクエストはそのタイムゾーンで処理
  されるため、新規記録の「今日」はリフター本人にとっての今日になります。
* **リーダーボードとプロフィール**に載るのは、公開を選んだリフター
  （サインアップ時は既定でオン、設定で変更可）の、承認済みの記録だけ
  です。男女は同一のボードに並び、それぞれの性別の基準に対する達成度で
  順位が決まります。公開ページにメールアドレスや体重が表示されることは
  ありません。
* **パスワードリセット**は、本番環境でメール送信が使えるようになるまで
  無効にしてあります（リンクも非表示）。
  `config/environments/production.rb` で SMTP を設定したうえで、
  `config/application.rb` に
  `config.x.password_resets_enabled = true` を設定してください。

## デプロイ

このアプリは [Kamal](https://kamal-deploy.org) でデプロイする構成です
（`config/deploy.yml` と `.kamal/` を参照）。永続ボリューム上の SQLite
を使う単一の Docker コンテナとして、どこにでもデプロイできます。想定
規模（ユーザー約500人、同時接続約20）であればこれで十分で、別途データ
ベースサーバーを用意する必要はありません。

```
bin/kamal setup   # 初回デプロイ
bin/kamal deploy  # 2回目以降
```

`bin/kamal deploy` を実行するマシンに `config/master.key`（git には
含めていません）を置き、`config/deploy.yml` にコンテナレジストリを設定
しておく必要があります。

## Windows 環境での注意点

* この環境で必要な範囲で、Rails の既定より踏み込んで `Gemfile` の gem
  バージョンを固定しています。たとえば `json` を `~> 2.9` に固定して
  いるのは、`json` 3.0.2 が ActiveSupport 8.1.3.1 において署名付き
  Cookie（セッション Cookie を含む）の読み取りを壊すためです。
  `bundle install` で `json` が 3.x に戻ってしまった場合は、再度固定して
  ください。
* `bin/rails` コマンドの実行時に、`.dll` プラグインが見つからないという
  `VIPS-WARNING` が出ることがあります。これは `libvips`（Active Storage
  の画像バリアント生成に使う `image_processing` gem 経由）が、この環境に
  入っていない任意のコーデックプラグインを探しているだけです。エラーでは
  なく無害な出力なので、無視して構いません。
